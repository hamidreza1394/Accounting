# مرجع کتابخانه‌ها، Kendo، پیوت و مهارت ui-ux-pro-max

این سند در 2026-10-27 از `docs/UI_COMPONENTS.md` جدا شد (محتوا بدون تغییر، جز اصلاح ارجاع‌های داخلی) تا آن سند برای هر کار UI کوتاه‌تر خوانده شود. قواعد عمومی UI (اصول، فرآیند افزودن کامپوننت، طراحی/سرعت/ویژوال، قانون محلی‌سازی آفلاین) در `docs/UI_COMPONENTS.md` می‌مانند و بر این سند مقدم‌اند. این سند را هنگام **انتخاب یا افزودن** کتابخانهٔ جدول/نمودار/تاریخ/پیوت، تصمیم دربارهٔ KendoReact یا اجرای مهارت `ui-ux-pro-max` بخوان.

## کتابخانه‌های پذیرفته‌شده برای جدول، نمودار و تاریخ

وضعیت: جهت انتخاب `Accepted` (درخواست صریح مالک محصول در 2026-10-27)؛ پیاده‌سازی در کد `NotImplemented`. تا این تاریخ در `ClientApp/package.json` فقط shadcn (Base UI، `class-variance-authority`، `cn`، `lucide-react` و CLI) نصب است و هیچ‌یک از کتابخانه‌های جدول/نمودار/تقویم زیر نصب نشده‌اند. افزودن هر مورد باز هم باید از «فرآیند افزودن کامپوننت» در `docs/UI_COMPONENTS.md` بگذرد: نسخهٔ دقیق، مجوز، سازگاری با React 19، اندازهٔ باندل پیش و پس از افزودن (خروجی واقعی `npm run build`) و قانون محلی‌سازی بالا.

| نیاز | انتخاب پذیرفته‌شده | شرط و نکته |
|---|---|---|
| جدول و گرید داده (دفتر روزنامه، فهرست‌ها، گزارش) | TanStack Table **v8** + TanStack Virtual، با کامپوننت‌های جدول shadcn | headless است و ظاهر را خود پروژه با Tailwind/shadcn می‌سازد. v9 هنوز بتاست؛ تا پایدار شدن روی v8 بمانید. برای چند هزار ردیف سمت کلاینت از مجازی‌سازی استفاده کنید؛ برای حجم بیشتر صفحه‌بندی/فیلتر سمت سرور. معناشناسی `<table>`/ARIA به عهدهٔ پروژه است. منابع ثانویه از ناسازگاری Table v8 با React Compiler خبر داده‌اند؛ پیش از استفاده با نسخهٔ واقعی تست شود. برای فهرست‌های ساده، گرید رایگان KendoReact هم طبق D-050 مجاز است (بخش پایین) |
| نمودار | نمودارهای shadcn/ui (مبتنی بر Recharts) | SVG و سبک؛ برای حدود زیر ۱۰ هزار نقطه مناسب است. نمودار داده‌ٔ بسیار حجیم یا نوع‌های خاص (heatmap، sankey) فقط با تصمیم جدا (Apache ECharts) |
| تاریخ شمسی | `Calendar` رسمی shadcn با تعویض `react-day-picker` به `react-day-picker/persian` | بدون کتابخانهٔ مستقل. ذخیره و ارسال همیشه ISO؛ نمایش جلالی از `src/lib/date.ts` (قرارداد فعلی). برای هر نمایش یا ورودی تاریخ، جهت RTL و ارقام فارسی تست شود |

**ممنوع مگر با ADR و تأیید صریح مالک:**
- بخش‌های پولی KendoReact/Telerik (از جمله PivotGrid، گروه‌بندی و aggregate گرید، خروجی Excel/PDF، master-detail): بدون خرید لایسنس و ADR ممنوع‌اند. بخش‌های **رایگان** KendoReact طبق D-050 و با شرط‌های بخش «KendoReact Free» پایین مجازند.
- AG Grid Enterprise: برای production لایسنس لازم دارد و قابلیت‌هایی مثل Server-side row model، pivot و گروه‌بندی پیشرفته در نسخهٔ پولی‌اند. AG Grid Community رایگان است ولی انتخاب نشده؛ استفاده از آن هم ADR می‌خواهد تا دو سیستم جدول هم‌زمان وارد پروژه نشود.
- ApexCharts: منابع از لایسنس پولی برای شرکت‌های دارای درآمد بالا خبر داده‌اند؛ پیش از هر استفاده مجوز واقعی از منبع رسمی بررسی شود.
- هر کتابخانهٔ UI یا سیستم طراحی دوم که با shadcn/Tailwind رقابت کند.

اطلاعات این بخش از مستندات رسمی و مقایسه‌های وب در 2026-10-27 جمع‌آوری شده است؛ نسخه‌ها، مجوزها و قیمت‌ها زود تغییر می‌کنند و پیش از افزودن هر وابستگی باید دوباره از منبع رسمی راستی‌آزمایی شوند.

مراجع: [تقویم فارسی shadcn](https://ui.shadcn.com/docs/components/calendar)، [راهنمای مجازی‌سازی TanStack Table v8](https://tanstack.com/table/v8/docs/guide/virtualization)، [AG Grid Community در برابر Enterprise](https://www.ag-grid.com/community-edition/).

## KendoReact Free (استفادهٔ مشروط؛ D-050)

وضعیت: تصمیم `Accepted` (درخواست مالک، 2026-10-27)؛ پیاده‌سازی `NotImplemented`: هیچ بستهٔ `@progress/kendo-react-*` هنوز نصب نیست.

**قاعدهٔ اصلی:** فقط کامپوننت‌ها و قابلیت‌هایی که در مستندات رسمی Telerik **نشان الماس ندارند** رایگان‌اند و بدون کلید لایسنس در production مجازند. نصب هر بسته از npm است. پیش از استفاده از هر کامپوننت، رایگان بودن همان قابلیت را در مستندات رسمی همان روز راستی‌آزمایی و در PR ثبت کنید.

| گرید KendoReact | رایگان | فقط پولی |
|---|---|---|
| داده | مرتب‌سازی، صفحه‌بندی، فیلتر، تغییر اندازهٔ ستون | گروه‌بندی ردیف و aggregate، master-detail، عملیات سمت سرور |
| خروجی و چاپ | خروجی CSV، چاپ | خروجی Excel و PDF، کپی/پیست، ادغام نمودار |
| عمومی | دسترس‌پذیری، صفحه‌کلید، بومی‌سازی | منوی زمینه، ابزارهای نوار ابزار |

**شرط‌ها (همه الزامی):**
1. قابلیت پولی بدون خرید لایسنس و ADR ممنوع است. کلید لایسنس یا نسخهٔ آزمایشی ۳۰ روزه هرگز در مخزن، PR یا production قرار نمی‌گیرد.
2. تقسیم کار با TanStack Table: گزارش‌ها و دفترهایی که گروه‌بندی، aggregate یا خروجی Excel می‌خواهند با TanStack Table ساخته می‌شوند (در Kendo رایگان نیستند). گرید رایگان Kendo فقط برای فهرست‌های ساده است. یک صفحه هرگز هر دو گرید را با هم ندارد. پس از پایلوت، مالک تصمیم می‌گیرد کدام گرید پیش‌فرض بماند.
3. قانون محلی‌سازی (بخش «قانون محلی‌سازی کامل دارایی‌ها» در `docs/UI_COMPONENTS.md`) بی‌استثنا اعمال می‌شود: بسته از npm، باندل با Vite، تم/آیکون/فونت محلی، و `npm run check:offline` پاس.
4. مستندات رسمی Telerik حالت RTL (با `dir` یا توکن RTL) و انطباق گرید با WCAG 2.2 AA را اعلام می‌کنند؛ رفتار واقعی آن‌ها در پایلوت دیده شود. ارقام فارسی و تقویم شمسی Kendo هنوز تأیید نشده‌اند. تاریخ شمسی با `Calendar` shadcn انجام می‌شود، نه ورودی تاریخ Kendo، مگر با راستی‌آزمایی جدا.
5. ظاهر باید با توکن‌های فرانو هماهنگ شود و با Tailwind/shadcn تداخل نگیرد. شروع با پایلوت یک صفحه و اندازه‌گیری حجم باندل پیش و پس (خروجی واقعی `npm run build`).
6. نسخهٔ دقیق بسته‌ها و توافق‌نامهٔ KendoReact پیش از نصب توسط مالک بازبینی و تأیید شود. کد منبع بسته‌ها در دسترس نیست (فقط برای مشتری تجاری)، پس اصلاح رفتار آن‌ها محدود است.

مراجع: [KendoReact Free](https://www.telerik.com/kendo-react-ui/components/free)، [Telerik Grid](https://telerik.com/kendo-react-ui/grid). مشخصات رایگان/پولی در 2026-10-27 از مستندات رسمی خوانده شده و باید قبل از نصب دوباره بررسی شود.

## گزارش پیوت (Pivot) و جدول‌های متقاطع

وضعیت: `Proposed` و `Deferred`؛ هیچ ابزار پیوتی هنوز انتخاب یا نصب نشده است.

| گزینه | وضعیت مجوز و نگهداری | نظر |
|---|---|---|
| KendoReact PivotGrid | premium؛ آزمایشی ۳۰ روزه برای production نیست | بدون خرید لایسنس ممنوع |
| FINOS Perspective | Apache 2.0؛ موتور WebAssembly، گروه‌بندی/تقسیم ستونی، فیلتر، aggregate و نمودار | کاندیدای آزمایشی (spike) |
| react-pivottable (MIT) | آخرین انتشار npm حدود ۴ سال پیش؛ نگهداری غیرفعال؛ باگ شناخته‌شده با React 18 | برای React 19 توصیه نمی‌شود |
| react-pivot (MIT) | گرید با قابلیت شبیه پیوت؛ ادعای سازگاری با React 19؛ بدون drag-and-drop واقعی | فقط برای گزارش ساده |
| Flexmonster | پوستهٔ React رایگان ولی خود پیوت لایسنس تجاری دارد | بدون لایسنس ممنوع |
| Syncfusion PivotView | لایسنس Community فقط برای سازمان‌های زیر ۱ میلیون دلار درآمد، حداکثر ۵ توسعه‌دهنده و ۱۰ کارمند | فقط اگر شرایط واجد باشد |
| AG Grid Enterprise | pivot و aggregation در نسخهٔ پولی | بدون لایسنس ممنوع |

**مسیر پیشنهادی:**
1. **اول بدون پیوت آزاد:** بیشتر گزارش‌های حسابداری (تراز آزمایشی، گردش حساب، دفتر کل، صورت‌های مالی) قالب ثابت دارند. جمع‌زدن و جدول متقاطع در SQL سمت سرور انجام شود و نمایش با TanStack Table (گروه‌بندی، گسترش ردیف، توابع aggregate) باشد.
2. **پیوت آزاد (کشیدن و رها کردن فیلد) فقط با نیاز واقعی:** یک spike با Perspective، با معیارهای: سازگاری با CSP پروژه (WebAssembly ممکن است سیاست جدا بخواهد)، محلی بودن همهٔ فایل‌ها از جمله `.wasm`، RTL و ارقام فارسی، حجم باندل، دسترس‌پذیری و نسخهٔ دقیق/مجوز. نتیجه با ADR ثبت شود.
3. **خرید لایسنس تجاری** (Kendo، AG Grid یا Flexmonster) فقط با تصمیم صریح مالک و ADR جدید.

مراجع: [KendoReact PivotGrid](https://www.telerik.com/kendo-react-ui/components/pivotgrid/)، [FINOS Perspective](https://github.com/finos/perspective). وضعیت نگهداری react-pivottable از Snyk Advisor و مجوزها از صفحات رسمی هر محصول در 2026-10-27 خوانده شد و پیش از هر تصمیم باید دوباره بررسی شود.

## مهارت ui-ux-pro-max برای کیفیت و زیبایی فرم‌ها

مهارت محلی `.claude/skills/ui-ux-pro-max` (منشأ و مجوز: `docs/THIRD_PARTY_SKILLS.md`) یک موتور جست‌وجوی محلی روی رهنمودهای UX است. استفاده از آن **اختیاری** و برای همهٔ Agentها و انسان‌هایی است که پوستهٔ دستور دارند، نه فقط Claude. شبکه ندارد و چیزی نصب نمی‌کند.

**اجرا (از ریشهٔ مخزن، با `python3` معمولی؛ نه `-I`، چون اسکریپت‌ها ماژول‌های هم‌پوشه را import می‌کنند):**
```bash
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "form inline validation error" --domain ux -n 3
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "form dialog table" --stack shadcn -n 3
python3 .claude/skills/ui-ux-pro-max/scripts/search.py "dashboard trend comparison" --domain chart -n 3
```

**چه زمانی:** پیش از ساخت یا بازبینی فرم، اعتبارسنجی و پیام خطا، دیالوگ، جدول، حالت‌های بارگذاری/خالی/خطا، دسترس‌پذیری و انتخاب نمودار. هر پرس‌وجو یک هدف مشخص و ۲ تا ۵ واژه داشته باشد.

**فقط این‌ها:** `--domain ux`، `--domain chart`، `--domain react`، `--stack shadcn`، `--stack react`.

**استفاده نشود (طبق بند تقدم داخل `SKILL.md` و قواعد `docs/UI_COMPONENTS.md`):**
- پالت، سبک، محصول، صفحهٔ فرود، تایپوگرافی، google-fonts و آیکون‌ها، و رنگ/فونتی که `--design-system` چاپ می‌کند: فرانو توکن‌های `src/styles/index.css`، فونت محلی Vazirmatn و `lucide-react` دارد.
- `--persist` و `--output-dir`: پوشهٔ `design-system/` را می‌سازند و منبع حقیقت طراحی دوم ایجاد می‌کنند؛ فقط با تأیید مالک.
- پیش‌تنظیم‌های GSAP/حرکت و هر آدرس CDN یا Google Fonts در خروجی یا نمونه‌کد.
- هر کتابخانه یا بستهٔ آیکونی که خروجی پیشنهاد کند: افزودنش تأیید مالک و ADR می‌خواهد.

**نحوهٔ به‌کارگیری خروجی:** خروجی پیشنهاد است، نه دستور. آن را با توکن‌ها، shadcn، RTL و قواعد `docs/UI_COMPONENTS.md` تطبیق بدهید؛ گزارش پایانی یا PR بنویسد کدام دستور اجرا شد و چه چیزی از آن به کار رفت یا رد شد. نتیجهٔ جست‌وجو همیشه دقیق نیست: در بررسی 2026-10-27 پرس‌وجوی «financial report comparison» در حوزهٔ نمودار نمودار شمعی (معاملاتی) داد که برای دفتر و گزارش حسابداری مناسب نیست، و «table sort filter keyboard» نتیجهٔ حوزهٔ واکنش‌گرا آورد. اگر نتیجه بی‌ربط بود، یک بار با عبارت یا حوزهٔ دقیق‌تر تکرار کنید و در غیر این صورت به رهنمودهای `docs/UI_COMPONENTS.md` برگردید.
