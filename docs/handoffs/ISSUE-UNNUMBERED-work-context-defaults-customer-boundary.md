# تحویل کار — پیش‌فرض انتخاب سال و مرز امنیتی مشتری

**وضعیت:** PR #65 در Draft؛ بدون Merge.  
**شاخه:** `feature/work-context-defaults-company-boundary`.

## درخواست و تصمیم‌های تأییدشده
- سال مالی جدیدترِ دارای دوره باز پیش‌انتخاب شود؛ در نبود دوره باز، جدیدترین دوره قابل ورود فقط‌خواندنی.
- شرکت پیش‌فرض باید تنظیمی جداگانه و مخصوص هر کاربر باشد؛ نباید صرفاً از آخرین محیط کاری نشست قبلی استنباط شود.
- گروه شرکتی و رابطه مالکیت نباید شرکت‌های CustomerAccountهای متفاوت را دربر بگیرند. تصمیم در D-037 ثبت شده است.

## تغییر فعلی
- `ClientApp/src/lib/fiscalYears.ts`: انتخاب سال پیش‌فرض به جدیدترین سال باز تغییر کرده؛ اگر سال باز وجود ندارد جدیدترین سال قابل ورود فقط‌خواندنی استفاده می‌شود. سال جاری فقط در مسیر تغییر محیط کاری حفظ می‌شود.
- `ClientApp/src/lib/fiscalYears.test.ts`: تست‌های انتخاب سال به‌روزرسانی شده‌اند.
- `docs/DECISIONS.md`: D-037 اضافه شد.
- `docs/INDEX.md`: فهرست ADR به‌روز شد.
- `docs/WORK_CONTEXT_SELECTOR_UI.md` و `docs/WORK_LOG.md`: وضعیت و محدودیت‌ها مستند شد.

## موارد تکمیل‌نشده
1. ذخیره و تغییر شرکت پیش‌فرض هر کاربر در سمت سرور (نیازمند مدل داده، API ضدجعل درخواست، UI تنظیم پیش‌فرض، تست و Migration).
2. برچسب «شرکت مادر / زیرمجموعه / مستقل» در ردیف شرکت.
3. مرز عملیاتی مشتری: D-020 می‌گوید CustomerAccount در سامانه فروشنده است و هنوز هیچ نگاشت معتبر Company به مرز مشتری در مدل عملیاتی وجود ندارد. قبل از نمایش رابطه‌ها باید شناسه مرز امنیتی بدون PII و روش provision آن طراحی شود؛ سپس تمام مسیرهای نوشتن/خواندن گروه و مالکیت در سرویس سمت سرور محدود و تست متقاطع شوند. تا آن زمان API/UI روابط گروهی مسدود بماند.
4. CI commit `8899ac1ae5b4e55ea35672d70abbfc02058e367d` را شکست‌خورده گزارش کرد، اما Job logs از GitHub connector قابل دریافت نبود؛ علت هنوز مشخص نیست. هیچ Build/Test محلی اجرا نشده است.
