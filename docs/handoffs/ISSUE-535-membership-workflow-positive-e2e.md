## شکاف
#524 و #525 فقط مسیر رد شدن را پوشش می‌دادند (و بخشی از آن هم فقط با API، بدون مرورگر).
مسیر موفق — «درخواست → دیدن در صف تأیید → انتخاب گروه دسترسی مجاز → تأیید → عضویت فعال + دسترسی واقعی»
— هیچ تست E2E نداشت؛ همین‌طور حالت‌های امنیتی اجباری (خودتأیید، تأییدکننده خارج از شرکت مقصد،
نقش بیرون از سقف واگذاری، بی‌اثر بودن Pending، درخواست Pending تکراری، مرز مشتری، شناسه دستکاری‌شده،
ضد جعل، نرخ محدود، و لغو مجوز پیش از تأیید). سه مورد از این‌ها در کد سرور پیاده شده‌اند اما هیچ تست
سرتاسری نداشتند.

## تغییرات
- `tests/e2e/lib/membershipFixture.mjs` — گراف داده‌ی ایزوله برای هر تست: `CustomerBoundary` مخصوص اجرا،
  دو شرکت داخل مرز (مبدأ/مقصد)، یک شرکت مرز خارجی، یک شرکت بدون مرز، یک شرکت **هم‌نام** با مرز دیگر
  (برای اثبات اینکه جستجو نام‌محور نیست)، نقش‌های واقعی با شناسه‌های مجوز از کاتالوگ مهاجرت‌شده،
  کاربران با هش رمز Identity V3. `destroy()` در ۹ جدول به ترتیب وابستگی پاک می‌کند.
  شناسه‌های برگشتی از SQL Server (که `uniqueidentifier` را با حرف بزرگ چاپ می‌کند) برای مقایسهٔ پایدار
  به حروف کوچک نرمال می‌شوند.
- `tests/e2e/lib/session.mjs` — ورود، `enterWorkspace` (برمی‌گرداند کدام حالت پوسته دیده شد:
  داشبورد/انتخاب شرکت/مسدود)، `callApi`/`post`/`antiforgery`، و `watchPage` برای خطای صفحه و
  نقض CSP.
- `tests/e2e/specs/membership-workflow.spec.mjs` — ۵ تست واقعی Playwright (Chromium، `fa-IR`،
  `Asia/Tehran`) روی سرور منتشرشده و SQL Server واقعی، بدون هیچ mock یا `page.route`:
  1. **موفق:** مالکیت درخواست از UI، بی‌اثر بودن Pending (بدون ردیف عضویت، `overview` = 404)،
     صف تأیید فقط با فیلدهای allowlist، `assignable-roles` فقط نقش مجاز، دو نقش ممنوعه با 403 رد
     می‌شوند، تأیید از دیالوگ UI، سپس `Approved` در DB با `ApprovedRoleId`/`DecidedByUserId`،
     Audit `CompanyMembershipApproved`، عضویت فعال با همان نقش، و دسترسی واقعی مقصد
     (`overview` = 200، `users` = 200، زمینه کاری).
  2. **رد:** رد از UI با دلیل، `Rejected` در DB و API، بدون عضویت، بدون دسترسی، و درخواست تکراری
     پس از رد مجاز اما همچنان بی‌دسترسی.
  3. **امنیت:** تأییدکنندهٔ شرکت دیگر 404؛ خودتأیید 403 حتی با داشتن مجوز در شرکت مقصد؛ لغو عضویت
     تأییدکننده پیش از تصمیم → 404 و بدون عضویت؛ نقش سیستمی و نقش بیرون سقف 403.
  4. **تکرار:** درخواست Pending تکراری 409؛ شناسهٔ شرکت خارج از مرز/ناموجود 404.
  5. **نرخ:** سقف درخواست‌های عضویت (۳۰ در ۶۰ ثانیه) با 429 و بدون ثبت ردیف اضافی.
