# تحویل کار — به‌خاطر‌سپاری نام کاربری و موارد بازمانده

## وضعیت
PR #67 (شاخه fix/login-remember-username-work-context) توسط مسئول مخزن Merge شده است. بازبینی پس از Merge، اصلاحات و تست‌های واقعی در `docs/handoffs/ISSUE-67-login-remember-username-review.md` ثبت شده‌اند؛ آن PR نیز نباید توسط Agent Merge شود.

## اصلاح ورود
- در صورت انتخاب گزینه، نام کاربری فقط پس از ورود موفق در کوکی HttpOnly با SameSite=Lax، Path=/ برای سازگاری با URLهای lowercase و انقضای یک‌ساله ذخیره می‌شود.
- در ورود بعدی، نام کاربری و تیک گزینه بازیابی می‌شوند.
- با برداشتن تیک، کوکی نام کاربری حذف می‌شود.
- رمز عبور توسط برنامه ذخیره نمی‌شود؛ فیلدها برای Password Manager مرورگر نشانه‌گذاری شده‌اند و راهنما تأیید prompt مرورگر را توضیح می‌دهد.
- تست E2E و تست‌های Integration برای رفتار کوکی و عدم پیش‌پرشدن رمز اضافه شده‌اند (نتایج واقعی در handoff ISSUE-67).

## کار باقی‌مانده — Issue #66
1. شرکت پیش‌فرض باید در سمت سرور و به‌ازای حساب کاربر ذخیره شود، نه فقط در کوکی مرورگر یا از آخرین نشست استنباط شود.
2. برای نمایش «مادر / زیرمجموعه / وابسته / مشارکت مشترک / مستقل» ابتدا باید مرز مشتری قابل‌اعتماد در محیط ابری مشترک طراحی و provision شود. D-020 می‌گوید CustomerAccount متعلق به سامانه فروشنده است؛ در مدل عملیاتی فعلی Company همان Tenant است و نگاشت Company→CustomerAccount موجود نیست.
3. پس از تعیین مرز، تمام مسیرهای ایجاد/ویرایش/خواندن گروه و مالکیت باید سمت سرور کنترل و با تست‌های منفی بین‌مشتری آزموده شوند؛ سپس API و UI نوع شرکت را از داده معتبر نشان دهند. نبود رابطه به‌تنهایی دلیل مستقل‌بودن نیست.
4. Migration افزایشی، تست‌های مدل/Integration/E2E، CI سبز و بازبینی نهایی لازم است.

## احتیاط
تا پیش از تکمیل مرز امنیتی، نوع شرکت را از جدول‌های مالکیت فعلی حدس نزن و رابطه‌های گروهی را به UI منتشر نکن. برای Issue #66 هر PR بعدی تا بررسی CI و موارد باقی‌مانده توسط مسئول مخزن Merge نشود.
