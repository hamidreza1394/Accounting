## نکتهٔ مهم: زمان UTC بدون `Z`
- سرور هیچ مبدل UTC برای `DateTime` ندارد و EF مقدار `datetime2` را با `Kind=Unspecified` می‌خواند؛ پس `System.Text.Json` زمان را **بدون `Z`** می‌نویسد و مرورگر آن را محلی (ساعت‌ها جابه‌جا) می‌خواند. با سرور زنده تأیید نشد (بازبین مستقل مطرح کرد، کد سرور شاهد آن است).
- در این PR پارسرهای فیلدهای `*Utc` (رویداد امنیتی، درخواست‌های عضویت) اگر offset نبود `Z` اضافه می‌کنند (`asUtcInstant`، تست دارد).
- **ریسک باز:** پارسرهای قدیمی‌تر (مثلاً `lastLoginDateTime`، `insertDateTime`، سوابق ورود) همین اصلاح را ندارند و ممکن است همین انحراف را نشان دهند. هر فیلد باید قبل از اصلاح تأیید شود که واقعاً UTC است؛ پیشنهاد: Backend یک مبدل سراسری `DateTime` ← UTC (`Z`) اضافه کند (تصمیم Backend/مالک).

## ۴) نیاز به Backend (ChatGPT) برای تکمیل S7
1. **انتخاب کاربر/شرکت**: فیلتر کاربر فقط از روی سلول جدول ممکن است. برای انتخاب مستقیم، API جستجوی کاربر برای مدیر نصب (فهرست کاربران `GET /admin/users?search=` موجود است و قابل‌استفاده) و **فهرست همهٔ شرکت‌های نصب** (امروز فقط شرکت‌های عضویت کاربر جاری هست) لازم است.
2. **ورود/خروج سراسری و نشست‌ها**: سوابق ورود امروز فقط برای حساب خود (`/me/login-history`) است؛ گزارش سراسری و ابطال نشست API ندارد.
3. **export و retention**: خارج از این برش و نیازمند سیاست جدا.
4. **فهرست انواع رویداد** از سرور (به‌جای فهرست داخل کلاینت) تا با رویداد جدید همگام بماند؛ تا آن زمان کد ناشناخته با خود کد نمایش داده می‌شود.
