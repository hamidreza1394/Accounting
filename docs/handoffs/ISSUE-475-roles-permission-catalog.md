## تصمیم‌های فنی
- **ساختار درخت (چک‌باکس والد فقط `indeterminate` native دارد؛ `aria-checked` حذف شد):** «فهرست چک‌باکس گروه‌بندی‌شده» انتخاب شد نه WAI-ARIA tree: چک‌باکس native صفحه‌کلید (Tab/Space) و صفحه‌خوان را رایگان می‌دهد. سربرگ هر زیرسیستم دکمهٔ افشاگر با `aria-expanded` است (Enter/Space) و `ArrowUp/ArrowDown/Home/End` بین سربرگ‌ها حرکت می‌کند. چک‌باکس والد هم `indeterminate` و هم `aria-checked="mixed"` دارد. برگ‌ها فقط برای گروه بازشده رندر می‌شوند؛ کاتالوگ بیش از ۴۰ مجوز بسته شروع می‌شود. جستجو ۱۵۰ms debounce دارد و ردیف‌ها `memo` هستند.
- **والد هنگام جستجو:** حالت سه‌گانه و «انتخاب/پاک‌کردن» فقط روی نتایج منطبق عمل می‌کنند (در رابط ذکر شده).
- **مشتق‌شده در UI (UI-derived):** گروه‌بندی منبع (بخش‌های میانی کد)، نشان نوع عملیات (آخرین بخش کد وقتی یکی از view/list/create/update/delete/manage است) و نام فارسی دو زیرسیستم `admin` و `trade`. هیچ‌کدام به سرور فرستاده نمی‌شود و معنای مجوزدهی ندارد؛ ستون کاتالوگ عمداً «نوع عملیات (استنباط‌شده)» نام دارد.
- **فیلتر سمت کلاینت در کاتالوگ** فقط چون endpoint بدون صفحه‌بندی و کوچک است؛ مقیاس بزرگ‌تر نیازمند پارامتر سرور خواهد بود. مجازی‌سازی ساخته نشد.
- **ایجاد نقش:** الگو در کلاینت روی انتخاب اعمال می‌شود و بدنه همیشه `{code, name, permissionCodes}` است؛ `templateCode` ارسال نمی‌شود چون سرور `permissionCodes` را مقدم می‌داند. اگر انتخاب نسبت به آخرین الگوی اعمال‌شده تغییر کرده باشد، ConfirmDialog پیش از جایگزینی می‌آید. انتخاب «بدون الگو» انتخاب فعلی را دست نمی‌زند. کد هنگام blur بزرگ‌حرف می‌شود. 409 بدون فیلد روی فیلد کد نمایش داده می‌شود.
- **ویرایش:** نقش از فهرست شرکت پیدا می‌شود (endpoint تکی نیست)؛ نبودن آن حالت «پیدا نشد» است. نقش سیستمی (یا نبودن تلمیح `admin.roles.manage`) فقط‌خواندنی است. هر ذخیره یک دیالوگ پیش‌نمایش دارد (عنوان، وضعیت، مجوزهای افزوده و حذف‌شده با نام و کد). غیرفعال‌سازی همان دیالوگ را `danger` می‌کند؛ پس تأیید غیرفعال‌سازی و پیش‌نمایش یک گام‌اند، نه دو دیالوگ. PUT بدنهٔ کامل است. پس از موفقیت لیست بدون پرش به حالت بارگذاری دوباره خوانده می‌شود.
- **انتخاب شرکت:** از `GET /companies` (شرکت‌های عضو کاربر) با پیش‌فرض شرکت کاری فعال. متن راهنما: «فهرست شرکت‌ها محدود به شرکت‌های عضو شماست.» شناسهٔ `?company=` خارج از فهرست به‌عنوان گزینهٔ صریح نگه داشته می‌شود و تصمیم با سرور است.
- عضویت (`POST …/members/{userId}`) هیچ UI ندارد (D-065).
- تصمیم معماری جدید (ADR) ثبت نشد؛ وابستگی npm جدید نیامد.

- همهٔ نوشتن‌ها با `sendJson` (anti-forgery) و Cookie هم‌مبدأ؛ بدون `localStorage`؛ بدون CDN.
- `can()` فقط تلمیح UI است؛ کاربر غیرمدیر در deep link «دسترسی ندارید» می‌بیند و هیچ درخواستی به `/admin/*` یا `/companies` نمی‌رود (تست).
- شناسه شرکت از URL به سرور فرستاده می‌شود، اما سرور بررسی نهایی را انجام می‌دهد (`AuthorizeInstallationAdministratorAsync` و 404 برای شرکت نامعتبر)؛ کلاینت به آن اعتماد مجوزدهی ندارد.
- هیچ Schema، Migration یا Server تغییر نکرد.

## نتیجهٔ بازبینی‌ها و اصلاحات
- **code-reviewer:** ۰ مانع قرارداد؛ ۱ یافتهٔ Major (فرم پس از ذخیره با دادهٔ قدیمی دوباره mount می‌شد) اصلاح شد: نقش ذخیره‌شده فوراً محلی اعمال می‌شود و ویرایشگر فقط با رسیدن داده (`version`) دوباره مقداردهی می‌شود؛ تست: پس از ذخیره عنوان و مجوزها مقدار ذخیره‌شده‌اند، دکمه غیرفعال، بدون `beforeunload` و بدون دیالوگ انصراف.
- **security-reviewer:** بدون Critical/High. Medium: سقف تفویض سمت سرور پیاده نشده است (مستند شد و Alert اطلاعاتی در صفحات ایجاد/ویرایش آمد). Lowها اصلاح شدند.
- اصلاحات Minor: (a) تغییر `company`/`roleId` در صفحهٔ mount‌شده حالت بارگذاری را برمی‌گرداند (فقط reload پس از ذخیره بی‌صدا است)؛ (b) `aria-checked` اضافی حذف شد (فقط `indeterminate` native)، حالت فقط‌خواندنی به‌جای `disabled` از `aria-readonly` و onChange بی‌اثر استفاده می‌کند تا فوکوس ممکن باشد، شمارندهٔ انتخاب دیگر live region نیست و فقط تعداد نتایج جستجو در یک `role=status` مخفی اعلام می‌شود، شمارندهٔ سربرگ گروه هنگام جستجو «نتیجه» دارد؛ (c) کدهای ناشناخته در بخش «مجوزهای ناشناخته» قابل برداشتن‌اند و در پیش‌نمایش «مجوز ناشناخته» نام دارند؛ (d) انتخاب الگو با واگرایی انتخاب ریست می‌شود و `?company=` ناشناس در صفحهٔ ایجاد پیام فارسی + انتخاب‌گر نشان می‌دهد.
- **محدودیت شناخته‌شده:** نگهبان dirty مثل فرم‌های کاربران فقط روی انصراف و `beforeunload` است؛ لینک‌های داخلی و Back را نمی‌گیرد.

## شکاف‌های API و موارد مشتق‌شده در UI
1. endpoint فهرست همهٔ شرکت‌های نصب برای مدیر نصب نیست؛ انتخاب‌گر فقط شرکت‌های عضو کاربر را دارد.
2. فهرست اعضای هر نقش نیست؛ فقط `activeMemberCount` (برای انتقال اعضا پیش از غیرفعال‌سازی، UI و API وجود ندارد).
3. GET تکی نقش نیست؛ کل فهرست شرکت بارگذاری می‌شود.
4. مدیر شرکت و delegation (سقف تفویض) پشتیبانی نمی‌شود؛ API فقط مدیر نصب را می‌پذیرد.
5. جست‌وجوی معکوس «کدام نقش‌ها این مجوز را دارند» نیست.
6. حذف یا غیرفعال‌سازی مجوز از کاتالوگ و حذف نقش در API نیست.
7. UI-derived: گروه‌بندی منبع، نشان عملیات، نام فارسی زیرسیستم‌های `admin` و `trade`.
