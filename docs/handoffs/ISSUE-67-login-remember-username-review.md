# تحویل کار — بازبینی و اصلاح PR #67 (به‌خاطر‌سپاری نام کاربری)

## وضعیت
PR #67 پیش از بازبینی توسط مسئول مخزن Merge شده بود (Merge commit 2f593fc). اصلاحات روی شاخه جدید `fix/login-remember-username-review` (مبنا: `main`) ارائه شده‌اند. Agent چیزی را Merge یا Close نکرده و `main` را مستقیم تغییر نداده است.

## ایرادهای واقعی و اصلاح
1. **Secure کوکی:** `Request.IsHttps` پشت Reverse Proxy به پیکربندی ForwardedHeaders وابسته است. قاعده اکنون با کوکی احراز هویت هم‌سو است: `Secure = !IsDevelopment || Request.IsHttps`. حذف کوکی با همان گزینه‌ها انجام می‌شود تا مرورگر آن را واقعاً پاک کند.
2. **اعتبارسنجی هنگام خواندن:** مقدار کوکی فقط اگر خالی نباشد، حداکثر `Constants.MaxLength.Username` (20) باشد و کاراکتر کنترلی نداشته باشد بازیابی می‌شود؛ خروجی با Tag Helper کدگذاری می‌شود.
3. **حذف شرطی:** `Set-Cookie` حذف فقط وقتی کوکی وجود دارد و گزینه خاموش است؛ این حذف در ورود ناموفق هم انجام می‌شود (ضد‌جعل درخواست پیش از آن اجرا می‌شود).
4. **متن گمراه‌کننده:** برچسب گزینه با محدودیت عدم‌فعالیت (نشست پایدار ولی لغزان ۳۰ دقیقه‌ای) صادقانه شد و یادداشت زیر فرم می‌گوید فقط نام کاربری ذخیره می‌شود و برای رمز باید prompt مرورگر تأیید شود (fa/en هماهنگ).
5. **تست ضعیف:** PR #67 فقط یک تست E2E داشت. ۱۰ تست Integration (`RememberedUsernameTests`، روی SQL Server واقعی) و ۳ تست E2E تازه افزوده شد؛ `signIn` در E2E نسبت به وضعیت تیک ایدمپوتنت شد.

## تصمیم‌ها
- کوکی `.Faranou.RememberedUsername`: فقط نام کاربری، HttpOnly، SameSite=Lax، Path=/، انقضا ۳۶۵ روز، IsEssential (فقط پس از تیک صریح کاربر؛ ترجیح کاربر است نه ردیاب).
- پس از خروج از حساب کوکی عمداً می‌ماند (کارکرد ویژگی)؛ پاک‌کردن با ورود بدون تیک. ریسک حریم خصوصی روی رایانه مشترک: فقط دیده‌شدن نام کاربری؛ افزودن «فراموش کن» نیاز به تصمیم محصول دارد.
- `autocomplete="username"` و `current-password` درست‌اند و دست نخورده‌اند؛ ذخیره رمز به تأیید prompt مرورگر وابسته است و تضمین نمی‌شود.
