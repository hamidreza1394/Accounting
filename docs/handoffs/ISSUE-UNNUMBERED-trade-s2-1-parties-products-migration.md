# Handoff — Trade S2-1: Migration سه جدول (UNNUMBERED)

- **Issue:** UNNUMBERED (شمارهٔ جعلی ساخته نشد). مبنا: D-081 (`Accepted`)، S2-1 در `docs/ROADMAP.md`.
- **خلاصه:** اولین Migration `TradeDbContext` (`InitialTradeMasterData`) فقط `trade.Parties`، `trade.PartyRoleAssignments`، `trade.Products` را می‌سازد، همراه FK مستأجرمحور `(TenantId, PartyId)` با Restrict و سه ایندکس یکتای فیلترشده `[IsDeleted] = 0`. `PartyBankAccount` و `ProductIdentifier` با `ToTable(..., t => t.ExcludeFromMigrations())` در مدل و ناوبری‌ها می‌مانند ولی جدولشان ساخته نمی‌شود (S5 / نیاز واقعی). `Down` به ترتیب وابسته‌ها را حذف می‌کند؛ schema `trade` را حذف نمی‌کند. به `DatabaseContext` و Migrationهای آن دست نخورد.
- **فایل‌ها:** دو Configuration (`PartyBankAccountConfiguration`، `ProductIdentifierConfiguration`)، `Persistence/Migrations/*` (Migration، Designer، Snapshot)، `tests/Template.Tests/Integration/TradeMasterDataMigrationSqlServerTests.cs`.
- **تولید:** با `dotnet ef migrations add` (ابزار 10.0.13)؛ دستی نوشته نشد.
- **آزمون واقعی:** (۱) آفلاین: ۳ تست دروازه — اسکریپت مدل، اسکریپت خود Migration (`IMigrator.GenerateScript`، یعنی `Up()` واقعی) دقیقاً سه `CREATE TABLE`، و بدون تغییر معلق مدل. (۲) SQL Server 2022 واقعی (کانتینر موقت، `FARANOU_REQUIRE_SQLSERVER=1`): `--filter TradeMasterData` = ۱۸ تست، ۱۸ موفق، ۰ Skip؛ شامل اعمال Migration روی پایگاه موقت، سه جدول، جدول تاریخچه، سه ایندکس با فیلتر، FK، رد تکرار فعال `(TenantId, Code)` در Parties/Products، اجازهٔ همان کد برای مستأجر دیگر و برای ردیف حذف‌شده.
- **یافتهٔ جانبی (جدا شد):** تست‌های HTTP دروازهٔ Trade روی `main` به‌صورت تصادفی (۴ از ۴ اجرا) شکست می‌خوردند (رقابت در `PermissionDefinitions`)؛ در PR جدا اصلاح شد (#639). پیش از ادغام آن، اجرای کل فیلتر `Trade` ممکن است یک شکست تصادفی نامرتبط نشان دهد.
- **بازبینی:** `code-reviewer` مستقل (شامل دید کوتاه امنیت/Tenant)؛ بدون Critical/High؛ دو Medium (مستندات تحویل، تست آفلاین روی خود Migration) اصلاح شد. بازبینی تخصصی `security-reviewer` (Schema حساس طبق CLAUDE.md بخش ث): نتیجه در توضیحات PR ثبت می‌شود؛ `architect` فراخوانی نشد چون طرح/Schema از پیش با D-081 و موجودیت‌های موجود ثابت بود و معماری تغییر نکرده است (انحراف از قاعده، گزارش شد).
- **اجرا نشد:** `Template.sln` کامل، ClientApp، E2E.
- **باز / تصمیم مالک (دست نخورده):** **مسیر اعمال Migration Trade در نصب مشتری وجود ندارد** — `DatabaseSchemaMigrator`/`Server/Program.cs` فقط `DatabaseContext` را Migrate می‌کنند. تا تصمیم، جدول‌های Trade در هیچ پایگاه استقراریافته‌ای ساخته نمی‌شوند (Trade با `DenyAll` بسته است). پیشنهاد: PR جدا با تأیید مالک.
- **ریسک:** تا S5، کدی که `BankAccounts`/`Identifiers` را بخواند یا ذخیره کند روی پایگاه Migrate‌شده به جدول ناموجود می‌خورد؛ در S2-3/S2-4 لمس نمی‌شوند. وقتی S5 پرچم را بردارد، Migration جدید و بازبینی امنیتی لازم است (داده بانکی حساس).
