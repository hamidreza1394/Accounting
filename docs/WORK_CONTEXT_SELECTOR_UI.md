# طراحی بصری و رفتار صفحه انتخاب شرکت و دوره مالی (2026-10-23)

> دامنه: فقط صفحه `/app/` در حالت «انتخاب» (`WorkContextSelector`) و صفحهٔ مسدود (`BlockedAccess`) که قرارداد آن‌ها در D-031/D-032 ثبت است. داشبورد، API و Schema تغییر نکرده‌اند. وضعیت: `Implemented` در شاخه `feature/work-context-selector-redesign` (PR ادغام‌نشده)؛ بررسی بصری و تست‌ها در بخش ۸ و handoff.

## ۱) رفتار
- **ترتیب:** اول دوره مالی (پنل راست)، سپس شرکت‌های مجاز همان دوره (پنل چپ)، یک ردیف برای هر شرکت.
- **API بدون تغییر:** دورهٔ مالی در سرور به هر شرکت تعلق دارد (`CompanyChoice.fiscalPeriods[]`، شناسهٔ جدا برای هر شرکت) و `POST /api/v1/context` همچنان `companyId` + `fiscalPeriodId` واقعیِ فهرست سرور را می‌خواهد. «سال مالی» در کلاینت با گروه‌بندی دوره‌ها بر اساس `startDate|endDate` (داده واقعی) ساخته می‌شود (`ClientApp/src/lib/fiscalYears.ts`). انتخاب جعلی، ارسال شناسه دلخواه و اعتبارسنجی همچنان فقط سمت سرور است (D-013).
- **ورود مستقیم** (فقط یک ترکیب شرکت/دورهٔ باز) و **صفحهٔ مسدود** مطابق D-031 بدون تغییر ماندند؛ هر ورود جدید دوباره می‌پرسد و انتخاب قبلی بی‌صدا پذیرفته نمی‌شود. ذخیره‌ای در `localStorage`/`sessionStorage`/URL نیست.
- **پیش‌انتخاب سخت‌گیرانه‌تر شد (تغییر رفتار):** فقط وقتی دقیقاً یک دورهٔ باز و یک شرکت ممکن است، پیش‌انتخاب می‌شود؛ شرکتی با یک دورهٔ باز و یک دورهٔ بسته دیگر خودکار انتخاب نمی‌شود تا کاربر ناخواسته وارد دوره‌ای نشود.
- **حالت‌ها:** دوره‌ای انتخاب‌نشده (راهنما و دکمهٔ غیرفعال)، دوره بسته (یادداشت «فقط مشاهده و گزارش‌گیری»)، دوره بایگانی‌شده (نمایش داده می‌شود ولی غیرقابل‌انتخاب)، شرکت بدون دورهٔ قابل ورود (در یادداشت نام برده می‌شود، ردیف انتخابی نیست)، جست‌وجو (نام یا شناسه ملی) برای فهرست طولانی، بارگذاری (اسکلت)، خطای API، منقضی‌شدن نشست (هدایت به ورود)، خطای تأیید، جلوگیری از ارسال دوباره.
- **داده‌های نمایش‌داده‌شده (همه واقعی از `GET /api/v1/context`):** عنوان/بازهٔ دوره، شمار شرکت‌های همان دوره، نام شرکت، شناسه ملی (در صورت وجود)، نقش، وضعیت دوره/دسترسی. هیچ فیلد ساختگی، مانده، سود و زیان، نمودار یا سند اخیر پیش از انتخاب نمایش داده نمی‌شود. شرکت‌های همنام فقط با شناسه ملی واقعی از هم متمایز می‌شوند.
- **ندیدن داده:** آیتم‌هایی مانند تعداد کاربران یا آخرین ورود شرکت در API فعلی وجود ندارد و نمایش داده نمی‌شود.

## ۲) هویت بصری
- ناوی (`#1c3d5a`) و سفید گرم/خاکستری‌های سرد، تأکید نارنجی/طلایی محدود (نوار انتخاب و حلقهٔ شمارهٔ مرحله)، رنگ فیروزه‌ای تیره فقط برای فوکوس. پس‌زمینه فقط CSS (گرادیان‌های ملایم + شبکهٔ کم‌رنگ)؛ بدون تصویر و افکت سنگین.
- انتخاب هرگز فقط با رنگ نشان داده نمی‌شود: نشانگر رادیویی/تیک، کادر ضخیم‌تر و نوار طلایی. کارت‌ها حالت‌های عادی/hover/focus/انتخاب‌شده/غیرفعال دارند. `prefers-reduced-motion` رعایت می‌شود.
- چیدمان: دسکتاپ دو پنل نابرابر با اسکرول کنترل‌شده فقط در فهرست شرکت‌ها؛ موبایل عمودی (دوره، سپس شرکت) با نوار اقدام چسبیده؛ صفحهٔ بزرگ متعادل با حداکثر عرض.

## ۳) لوگو
- منبع رسمی: `Server/wwwroot/images/faranou-logo.jpg` (در واقع WebP ‏1376×752 با پس‌زمینه سفید-گرم). SVGهای قدیمی (`faranou-logo-mark.svg`، `faranou-mark.svg`) با فایل رسمی تفاوت دیداری دارند و کاشی آبی قبلی کلاینت React ساختگی بود؛ لوگوی قدیمی تراز آوا استفاده نشده است.
- مشتق: نشان رسمی از همان فایل **بریده** شد (حذف پس‌زمینه با آستانه رنگ، بدون بازطراحی) → `Server/wwwroot/images/faranou-brand-mark.webp` (432×416، حدود ۴۳KB). متن «فرانو / نرم‌افزار حسابداری هوشمند» متن زنده است نه تصویر.
- باقی‌مانده: نسخهٔ SVG برداری رسمی در مخزن نیست؛ در صورت وجود، باید جایگزین شود.

## ۵) مرور محصولات (فقط منابع رسمی؛ کپی‌برداری نشده؛ ادعای دسترسی داخلی نیست)
- **Dynamics 365 Business Central** («Switching to Another Company or Environment»): جابه‌جایی شرکت با پنل انتخاب و مفهوم Environment جدا از Company؛ درس: نام شرکت و محیط باید صریح و قابل تمایز باشد.
- **NetSuite** («Roles and Accounts»): صفحهٔ انتخاب نقش‌های حساب جاری در بالا و «تعویض حساب» جدا؛ نقش آخر به خاطر سپرده می‌شود. درس: نقش در ردیف نمایش داده شود؛ ما ذخیرهٔ انتخاب قبلی را عمداً نمی‌پذیریم (D-031).
- **SAP Business One** (صفحهٔ آموزشی رسمی): انتخاب شرکت در ورود و «Change Company». درس: انتخاب پیش از ورود به محیط کاری.
- **محدودیت:** صفحهٔ رسمی سپیدار قابل خواندن نبود (`robots` مانع)، جست‌وجوی رسمی حسابفا و راهکاران به منبع قابل‌اتکا نرسید؛ بنابراین هیچ ادعایی دربارهٔ آن‌ها ثبت نمی‌شود. هیچ منبع غیررسمی استفاده نشد.

## ۷) امنیت
بدون تغییر سمت سرور. تأیید: انتخاب فقط از فهرست سرور ساخته می‌شود؛ ارسال شرکت/دورهٔ غیر مال کاربر 404 یکسان می‌گیرد (تست E2E موجود)؛ توکن Anti-forgery لازم است؛ هیچ ذخیرهٔ مرورگری؛ نام شرکت به‌صورت متن React رندر می‌شود (بدون `dangerouslySetInnerHTML`)؛ CSP (`img-src 'self' data:`، `font-src 'self'`) بدون تغییر کار می‌کند؛ خطای API پیام عمومی نشان می‌دهد.

## ۸) آزمون‌های واقعی این تغییر

- `dotnet test` روی SQL Server 2022 واقعی (Docker): ۴۹۷ کل، ۴۹۵ موفق، ۲ Skip، ۰ شکست.
- E2E Playwright/Chromium روی سرور منتشرشده و SQL Server واقعی: ۲۴/۲۴؛ سناریوهای جدید: همنام‌ها با شناسه ملی و سال بایگانی غیرقابل‌انتخاب، تغییر سریع سال، ورود یک‌باره بدون دوبار ارسال، فقط منابع محلی و نشان رسمی و فونت Vazirmatn.
- بررسی بصری (Chromium، چهار اندازه: ۳۶۰، تبلت، لپ‌تاپ ۱۳۶۶×۷۶۸، دسکتاپ بزرگ؛ حالت‌های frank/alice/dave/erin): بدون سرریز افقی و بدون خطای Console. بازبینی انسانی نهایی با مرورگر واقعی کارفرما انجام نشده است.
- اجرا نشده: تست دسترس‌پذیری ابزاری (axe)، صفحه‌خوان، Safari/Firefox، لب‌تاپ/موبایل فیزیکی، تست بار.


## ۹) طرح نهایی تأییدشده (2026-10-23، شاخه `feature/work-context-selector-final-design`)
طرح مرجع محصول (تصویر تأییدشده) روی صفحهٔ واقعی پیاده شد؛ بخش‌های ۱ تا ۸ بالا تا جایی که با این بخش تعارض ندارند معتبرند.

**پیاده‌شده از مرجع:** هدر تمام‌عرض سرمه‌ای (لوگوی رسمی، نام و username کاربر، آواتار حرف اول، دکمهٔ خروج دایره‌ای با فلش نارنجی؛ بدون زنگ/تنظیمات/خانه و بدون «فرانو - داشبورد»)؛ عنوان «فرانو - دوره مالی»؛ چیپ «شما به N شرکت دسترسی دارید» با N واقعی؛ پنل دوره‌های مالی راست، باریک (۲۶٫۲۵rem) با زمینهٔ آبی ملایم؛ پنل شرکت‌ها چپ و پهن با یک ردیف تمام‌عرض برای هر شرکت؛ جست‌وجوی واقعی هر دو؛ نوار پایین سرمه‌ای با خلاصهٔ انتخاب و دکمهٔ بزرگ «ورود به محیط کاری» (۲۷۲×۶۸، گرادیان نارنجی)؛ ارتفاع روان پنل‌ها (`lg:h-dvh`، حداقل ۴۴rem) تا نوار پایین روی لیست‌ها نیفتد و لیست‌ها مستقل اسکرول شوند؛ موبایل عمودی.

**انحراف‌های آگاهانه از مرجع و دلیل:**
- برچسب‌های «شرکت مادر / زیرمجموعه / هم‌گروه» و چیپ «x از y شرکت همگروه»: مدل داده گروه شرکتی ندارد (D-033..D-035 `NotImplemented`) و اختراع نمی‌شود؛ به‌جای آن نقش واقعی کاربر (`roleName`) نمایش داده می‌شود.
- آیکون شرکت‌ها: ساختمان عمومی (لوگوی اختصاصی شرکت‌ها در API نیست)؛ آواتار فقط حرف اول (عکس در API نیست)؛ خط دوم کنار نام، username است (نقش شغلی در API نیست).
- شعار «مدیریت مالی هوشمند…» و عکس ساختمان نوار پایین: منبع/مجوز نامشخص؛ به‌جای آن خطوط اسکای‌لاین اورجینال (SVG درون‌خطی).
- پس‌زمینه: SVG درون‌خطی و CSS محلی (رشته‌کوه محو، خطوط طلایی، میله‌های صعودی، شبکهٔ ملایم) تقریبی از مرجع است؛ پیکسل‌به‌پیکسل نیست.
- متن «کد ملی» مطابق مرجع آمد؛ در عرف حقوقی برای شخص حقوقی «شناسه ملی» رایج‌تر است. نیاز به تأیید محصول.
- پنل دوره: یادداشت پایین «دوره بسته فقط برای مشاهده و گزارش‌گیری است.» (متن واقعی رفتار D-032).
- وضعیت دورهٔ نوار پایین علاوه بر رنگ با متن (فعال/بسته شده/بایگانی) نشان داده می‌شود.
- پیش‌انتخاب: همان قاعدهٔ سخت‌گیرانه؛ فقط یک سال و یک شرکت بی‌ابهام پیش‌انتخاب می‌شود، نه بر اساس ترتیب فهرست. مدل فعلی «دوره جاری/شرکت پیش‌فرض» ندارد؛ تغییر دیتابیس انجام نشد.

**آزمون:** ۸۵ تست Vitest؛ ۲۵ تست E2E (شامل «final design»: هدر بدون کنترل ساختگی، ردیف‌های تک‌ستونی، جست‌وجوی دوره و شرکت بر اساس شناسه)؛ ۴۹۷ تست .NET (۴۹۵ موفق، ۲ Skip) روی SQL Server واقعی. بازبینی بصری در Chromium (۱۷۱۰×۹۲۰، ۱۳۶۶×۷۶۸، تبلت، موبایل) انجام شد؛ بازبینی انسانی نهایی و مقایسهٔ پیکسلی ابزاری انجام نشد.
